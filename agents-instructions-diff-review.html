## Prompting and Agent Instructions

It is observed that models tend to do way too much when asked to write agent instructions or prompts. The more instructions we add, the harder it is to tune to get the result we want. Removing or abstaining from writing certain parts of instructions is just as much a lever as writing instructions. Be very intentional with each instruction you add because adding unnecessary, incorrect, or misinterpretable instructions can be more harmful than nothing at all.

Prefer concise, efficient instructions when asked to write persistent prompts or agent instructions. Favor outcome based persistent prompts and instructions with verifiability. Convey intention and/or philosophy. Be careful not to over-prescribe implementation details or turn assumptions about how work should be done into persistent instructions.

By persistent prompts or instructions, I generally refer to instructions that are persisted, saved, potentially iterated on such as `CLAUDE.md`, `AGENTS.md`, skills, plans, specs, etc. This does not necessarily apply to things like subagents that you spin up since these are not prompts that are persisted.
